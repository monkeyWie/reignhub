## 下载和启动

从[服务端下载](/zh-CN/download#server)选择与你的系统和 CPU 匹配的 `reignhub-server` 压缩包。对照 GitHub Releases 中该文件的 SHA-256 校验，解压后进入包含程序和 `config.json` 的目录。程序内置 Web 控制台。

```sh
./reignhub-server --version
./reignhub-server
```

Windows PowerShell 下使用 `.\reignhub-server.exe`。在服务器上打开 `http://localhost:26330/chat/`。公网访问时，用 HTTPS 反向代理转发至 26330/TCP，或配置 `services.control.tls` 下的 `certFile` 和 `keyFile`。默认探测端口为 26331/UDP 和 TCP，原生中继为 26332/UDP 和 TCP。若经 NAT 或反向代理，请将 `services.stun.publicAddress` 和 `services.relay.native.publicAddress` 设为客户端可达的地址。

也可以从源码仓库启动 Docker Compose：

```sh
docker compose -f deploy/service/compose.yaml up -d --build
```

## 配置功能与端口

服务从当前工作目录读取 `config.json`。解压包已附带模板。单独安装二进制时，在服务目录执行一次 `reignhub-server --init` 生成模板，编辑后运行 `reignhub-server`。已有配置会保留。也可以用 `--config PATH` 指定其他文件。数据库、Web 目录和 TLS 文件的相对路径以配置文件所在目录为准。

三个服务组默认都启用。如果用 Worker 做中控，Go 节点只提供 STUN 和中继，可使用这份 `config.json`。

```json
{
  "services": { "control": { "enable": false } }
}
```

禁用本地中控后，26330 仍提供独立的 WebSocket 中继。Worker 可以用 `EXTERNAL_RELAYS` 登记此节点的 WSS 域名。

从 RC.2 升级时，把原来靠省略来关闭的服务显式设为 `enable: false`。STUN 默认使用 26331，原生中继使用 26332，两个端口均同时监听 UDP 和 TCP。

修改后重启 Go 服务。中控可以用 `services.control.stunServers` 在内置的 Cloudflare、Google 和哔哩哔哩（`stun.chat.bilibili.com:3478`）UDP 节点之外追加探测节点，用 `services.control.externalRelays` 登记外部中继的地址和节点凭据。

## 安装与升级

Linux 可使用源码仓库 `deploy/service/` 目录中的 systemd 服务文件。升级时保留 SQLite；复制备份前先停止服务并一并保留 WAL/SHM，或使用 SQLite 备份功能。数据库包含固定的服务 ID、签名密钥、设备元数据、凭据哈希与配对权限，不保存聊天明文。重启后检查 `/healthz`、`/p2p/config` 和实际配对连接。

仓库 `deploy/service/README.md` 提供 Docker、Nginx、systemd 和安装脚本详情。直接 `go install` 的源码构建没有自动内嵌 Web 资产，应使用发布二进制或设置 `services.control.webDir` 指向构建好的控制台目录。
