## Deployment button

Open [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/monkeyWie/reignhub), authorize your Cloudflare account and follow the setup flow.

Deploy the **root repository, not only `apps/site`**: the Worker depends on the connection core in the same pnpm workspace. Provision a Worker, one D1 database and a SQLite Durable Object.

Grant the Worker, D1 and Durable Object permissions requested by the setup flow, then save the assigned service URL and resource bindings.

## Manual deployment

Install Git, Go (see `go.mod`), Node.js 24 and pnpm 10.34.5, and prepare a Cloudflare account:

```sh
git clone https://github.com/monkeyWie/reignhub.git
cd reignhub
corepack enable
pnpm install --frozen-lockfile
pnpm exec wrangler login
pnpm build:web
pnpm run deploy
```

Use `pnpm run deploy`, not pnpm's own deploy subcommand. The deployment script initializes D1 after resource creation; requests may fail until initialization completes.

## Preserve resource bindings

Save the assigned D1 database ID in `wrangler.jsonc`. Reuse that database for future releases so that the device directory and service identity remain intact.

Check the service:

```sh
curl https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/healthz
curl https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/p2p/config
```

Health should succeed and config should contain connection capabilities and the signing identity. Open the same-origin `/chat` page and set the Worker root URL in native clients.

## Domains and origins

Bind a custom domain in Cloudflare and use HTTPS after DNS and certificate activation. Keep Web, API, signaling and relay on the same origin.

To allow additional Web origins, set `ALLOWED_ORIGINS` to exact comma-separated origins. The current origin is allowed by default. Broad wildcards are not a replacement for pairing authorization.

## Console-only deployment

The root URL redirects to `/chat/`. This package includes only the NSGo Web console, connection APIs and encrypted relay. It does not build or bundle Next.js, marketing pages, documentation or search indexes. Website content is published only through the separate official website CI; no `SITE_URL` or website branding variables are needed.

## Local verification

```sh
pnpm exec wrangler d1 migrations apply DB --local
pnpm exec wrangler dev --port 8787
```

Open `http://localhost:8787/chat`. Local resources are separate from production D1; never point development at a real user's device state directory.

Browsers can use an independent Go relay. Set the WSS origin, optional native addresses and node credential in the same entry of the `EXTERNAL_RELAYS` secret. [Configure a relay node](/docs/self-hosting/probe)
