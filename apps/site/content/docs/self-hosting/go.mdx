## Download and start

Choose the `reignhub-server` archive for your OS and CPU from [server downloads](/download#server). Verify it against the archive’s SHA-256 digest on GitHub Releases, extract it and enter the directory containing the executable and `config.json`. The binary embeds the Web console.

```sh
./reignhub-server --version
./reignhub-server
```

On Windows PowerShell, run `.\reignhub-server.exe`. Open `http://localhost:26330/chat/` on the server. For public browser access, proxy HTTPS to port 26330/TCP or set `certFile` and `keyFile` in `services.control.tls`. Expose 26331/UDP and TCP for STUN and 26332/UDP and TCP for native relay. Behind NAT or a reverse proxy, set `services.stun.publicAddress` and `services.relay.native.publicAddress` to addresses reachable by clients.

To use Docker Compose, run this from the source repository:

```sh
docker compose -f deploy/service/compose.yaml up -d --build
```

## Configuration

The server reads `config.json` in the working directory. Archives include the template. With a binary-only install, run `reignhub-server --init` once in your service directory, edit the file and run `reignhub-server`. Initialization preserves existing files. Use `--config PATH` to select a different file. Relative state, Web and TLS paths resolve from the config directory.

All three service groups default to enabled. To use a Worker for control and run only STUN and relay on this machine, set `config.json` to:

```json
{
  "services": { "control": { "enable": false } }
}
```

With local control disabled, port 26330 serves the independent WebSocket relay. A Worker can advertise its public WSS origin in `EXTERNAL_RELAYS`.

When upgrading from RC.2, set `enable` to `false` for any service that was disabled by omission. STUN uses port 26331 and the native relay uses port 26332 over both UDP and TCP.

Restart the Go service after editing. A control service can use `services.control.stunServers` to add discovery nodes alongside the built-in Cloudflare, Google and Bilibili (`stun.chat.bilibili.com:3478`) UDP nodes and `services.control.externalRelays` to register relay addresses and node credentials.

## Installation and upgrades

For Linux, use the systemd unit in the source repository’s `deploy/service/` directory. Preserve the SQLite database when upgrading. Stop the service before copying the database and any WAL/SHM files, or use SQLite's backup API. The database contains the persistent service ID, signing key, device metadata, credential hashes and pairing permissions, but no chat plaintext. Check `/healthz`, `/p2p/config` and an actual paired connection after restarting.

The repository's `deploy/service/README.md` contains Docker, Nginx, systemd and installer details. Building from source with `go install` only embeds Web when release assets have been staged; use a release binary or set `services.control.webDir` in config.json.
