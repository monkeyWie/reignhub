## 一键部署

打开仓库中的 [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/monkeyWie/reignhub) 入口，授权你自己的 Cloudflare 账号，按向导创建服务。

部署根仓库，**不要只选择 `apps/site` 子目录**，因为 Worker 依赖同一 pnpm workspace 中的连接核心。向导需要配置 Worker、一个 D1 数据库和 SQLite Durable Object。

按照向导授权 Worker、D1 和 Durable Objects 所需权限，完成后保存分配的服务地址与资源绑定。

## 手动部署

需要 Git、Go（版本见 `go.mod`）、Node.js 24、pnpm 10.34.5 和 Cloudflare 账号。在自己的目录克隆开源仓库：

```sh
git clone https://github.com/monkeyWie/reignhub.git
cd reignhub
corepack enable
pnpm install --frozen-lockfile
pnpm exec wrangler login
pnpm build:web
pnpm run deploy
```

注意使用 `pnpm run deploy`，避免调用 pnpm 自身的 deploy 子命令。首次资源创建后，部署脚本初始化 D1；初始化完成前请求可能暂时不可用。

## 保存资源绑定

检查 Wrangler 输出，在 `wrangler.jsonc` 中保留这次分配的 D1 数据库 ID。后续发布继续使用同一个数据库，避免重复创建后丢失设备目录和服务身份。

部署后检查：

```sh
curl https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/healthz
curl https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/p2p/config
```

健康检查应返回成功；配置端点应包含这套服务的连接能力和签名身份。打开同源 `/chat` 页面，再把 Worker 根地址填入原生客户端。

## 自定义域名与来源限制

可以在 Cloudflare 中给 Worker 绑定自定义域名，等待 DNS 与证书生效后使用 HTTPS 地址。Web、API、信令和中继保持同源部署。

需要允许额外 Web 来源时，用 `ALLOWED_ORIGINS` 配置精确的逗号分隔 origin。当前服务自身的 origin 默认允许。不要用宽泛通配符替代配对授权。

## 仅部署控制台

根地址统一跳转 `/chat/`。开源包只包含 NSGo Web 控制台、连接 API 和加密中继，不构建或打包 Next.js、官网、文档与搜索索引。官网内容只通过独立的官方 CI 发布，无需配置 `SITE_URL` 等官网构建变量。

## 本地验证

```sh
pnpm exec wrangler d1 migrations apply DB --local
pnpm exec wrangler dev --port 8787
```

访问 `http://localhost:8787/chat`。本地资源与生产 D1 分开，开发时不要指向真实用户的设备状态目录。

浏览器也可以使用自部署的 Go 中继。在 `EXTERNAL_RELAYS` Secret 的同一个节点条目里填写 WSS 域名、可选的原生地址和节点凭据。[添加中继节点](/docs/self-hosting/probe)
