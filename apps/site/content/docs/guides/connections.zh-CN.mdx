## 连接顺序

<ArchitectureDiagram kind="connection" />

1. 通过服务完成设备发现、配对和加密握手。
2. 收集局域网、IPv6、公共 STUN 与可选自建探测器提供的候选地址。
3. 原生端并行尝试 WebRTC／UDP 和原生 TCP 路径；浏览器尝试 WebRTC。
4. 无法直连时，在服务允许的情况下使用该服务的加密 WebSocket 中继。

公共和自建探测器并行辅助直连。打洞成功后的业务数据直接在设备间传输，但信令连接仍用于维持设备状态等能力。

## 浏览器与原生端的区别

| 能力                       | 原生桌面／手机 | 浏览器                 |
| -------------------------- | -------------- | ---------------------- |
| WebRTC 数据通道            | 支持           | 支持，取决于浏览器环境 |
| 原生 TCP 打洞              | 支持           | 无原始 TCP Socket API  |
| 加密 WebSocket 中继        | 服务允许时可用 | 服务允许时可用         |
| 作为被控电脑管理本机 Agent | 桌面端支持     | 不支持                 |

## HTTPS 与端口

客户端只填服务根地址，例如 `https://reignhub.example.com`，探测器从 `/p2p/config` 自动发现。Cloudflare Worker 提供 HTTPS／WSS。

Web 的加密 API、剪贴板和部分连接能力需要安全上下文。公网浏览器应使用 HTTPS；localhost 具有浏览器的开发例外。不要把“HTTP 页面能打开”等同于完整的浏览器远控能力。

## 无法打洞怎么办

NAT、防火墙和企业 Wi-Fi 隔离都可能阻止直连。官方免费账号没有官方业务中继权益；付费方案开放后可按套餐回退官方中继。自建开源 Worker 可用自己的中继。

可选 Go 节点提供 TCP／UDP 探测，也可以通过 WSS、QUIC 和 TCP 中继流量。[部署探测器](/docs/self-hosting/probe)。
